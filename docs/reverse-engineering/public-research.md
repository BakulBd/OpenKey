# Public AK820 research: comparison

Survey of every public implementation found on 2026-10-07, plus the official AJAZZ software.
Claims are recorded as each source makes them. Where sources conflict, the conflict is listed, not
merged. OpenKey's own conclusions, with their evidence, are in the [research log](../RESEARCH_LOG.md)
and the protocol specifications under [`docs/protocol/`](../protocol/).

## Main finding

"AK820" covers at least **six incompatible firmware/protocol families**. They share marketing names
and sometimes the same USB VID:PID (`0C45:8009` is a generic Sonix PID used by many AJAZZ boards).
Only HID descriptors and the device's answers can tell them apart:

| Family (OpenKey id)            | Typical identity                                      | Configuration pipe                                        | Data / TFT pipe                         | Framing                                                            |
| -------------------------------- | ----------------------------------------------------- | --------------------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------ |
| `sonix-feature` (Windows driver) | `0C45:8009` "AK820 MAX" or "AK820"                    | FF13:0001, 64-byte **feature** reports, no report ID      | FF68:0061, **4096-byte output** reports | `04 <cmd> <sub> 00×5 <arg8> <arg9>`, ack = echo with byte 3 = `01` |
| `sonix-aa55` (online driver)     | `0C45:8009` "AK820"; AK820 MAX HE `0C45:80B1`         | FF68 (or FF80/FF00/FF01/FF1B), **64-byte output** reports | FF67, 4104-byte output                  | `AA cmd len addrLo addrHi … ` → `55 cmd …`                         |
| `sonix-dongle`                   | `0C45:FDFD` "2.4G Dongle", `05AC:024F`                | vendor collection, 32-byte output                         | —                                       | 32 bytes, byte 31 = additive checksum                              |
| `crs-aa55cc33`                   | `1A2C:A036`, `1A2C:8FFF` (a CRS-MCU "AK820 Max Plus") | FF02, 64-byte output                                      | —                                       | `AA 55 CC 33 <op> …`                                               |
| SinoWealth                       | `258A:010C`, `3554:FA09` (an "AK820 MAX")             | vendor collection, feature report ID 6                    | —                                       | 9-byte feature reports                                             |
| `qmk-via`                        | community QMK on AK820 Pro                            | FF60:0061 raw HID, 32 bytes                               | —                                       | VIA                                                                |

The user's AK820 MAX PLUS TFT (`0C45:8009`, "AK820 MAX", bcdDevice 1.07) belongs to the first family.

## Conflicts and how they were resolved

| Claim                                                      | Sources                                                                | Resolution                                                                                                                                                                                                |
| ---------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Feature reports (`04` framing) vs output reports (`AA/55`) | gohv, MemerGamer, kabelklaus, aks075 vs wsclx, online driver           | **Both exist.** Firmware family is visible in the descriptors: FF13 feature + 4096-byte FF68 → `04` framing; 64-byte FF68 → AA/55. Verified for the MAX PLUS on hardware (START echoed as `04 18 00 01`). |
| Lighting delimiter `55 AA` vs `AA 55`                      | gohv, MemerGamer, kabelklaus vs online driver, official Windows driver | Official Windows driver writes the 16-bit immediate `0x55AA` little-endian → bytes `AA 55`.                                                                                                               |
| `IMAGE_CFG` byte 2 = 0x02 vs 0x03                          | gohv vs aks075 capture                                                 | Byte 2 is the **screen slot** (`LCDViewList::GetCurSel() + 1`). Both values are slots; AK820 MAX has one slot (`gif_count="1"`).                                                                          |
| Time data byte 10 = 0x04                                   | gohv, aks075, Beattrey                                                 | Day of week from `GetLocalTime` (`wDayOfWeek`); the constant was the capture day (Thursday).                                                                                                              |
| Direction codes Left 0/Down 1/Up 2/Right 3                 | gohv                                                                   | Official Windows driver UI: left 0, right 1, up 2, down 3. Online driver uses its own enum. To be verified on hardware.                                                                                   |
| TFT delay units 2 ms vs "×5"                               | aks075 vs wsclx                                                        | Windows driver divides ms by 2. Online driver multiplies its UI value (default 10) by 5; consistent with 2 ms units if the UI value is in 10 ms steps (INFERRED).                                         |
| `0xFEFE` is Bluetooth vs 2.4 GHz                           | wsclx vs aks075                                                        | Unresolved across models; on Linux the HID bus type decides (Bluetooth = bus 0x0005).                                                                                                                     |
| Chunk size 4123 vs 4096                                    | gohv/TaxMachine vs aks075/official                                     | 4096 + report ID byte; 4123 is not in any official code path.                                                                                                                                             |
